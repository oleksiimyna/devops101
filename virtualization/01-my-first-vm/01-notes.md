# Модуль 02 — Linux та VirtualBox

## 1. Віртуальні машини та гіпервізор

**Віртуальна машина (VM)** — програмно створений комп'ютер, який працює всередині фізичного комп'ютера. У VM можна встановити окрему операційну систему, наприклад Ubuntu Server, не перевстановлюючи Windows на основному ПК.

- **Хост (host)** — фізичний комп'ютер та його основна ОС.
- **Гість (guest)** — операційна система всередині VM.
- **Гіпервізор** — програмний рівень, який створює та запускає VM, розподіляє між ними ресурси хоста й керує віртуальним обладнанням.
- **vCPU** — віртуальний процесор, який гіпервізор надає гостьовій ОС.
- **RAM VM** — частина оперативної пам'яті, яку VM бачить як власну.

У цій лабораторній роботі використовується Oracle VirtualBox на Windows, а гостьова система — Ubuntu Server 26.04.1 LTS.

## 2. Конфігурація лабораторної машини

Основна VM: `devops-lab-manual`.

Початкова конфігурація під час створення:

- RAM: 4096 MB;
- CPU: 2;
- диск: VDI, 30 GB;
- мережа: NAT;
- ОС: Ubuntu Server 26.04.1 LTS.

Перед завданням зі збільшення ресурсів у VirtualBox було 5120 MB RAM і 3 CPU. У завданні 4 параметри збільшено до 6144 MB RAM та 4 CPU.

## 3. Snapshot

**Snapshot** — контрольна точка стану VM, до якої можна повернутися після невдалих змін або експерименту.

У лабораторній роботі використовувалися:

- `clean-install` — контрольна точка після встановлення Ubuntu;
- `clean` — контрольна точка робочої Ubuntu після зміни hostname, використана для відновлення після пошкодження DNS.

Snapshot зручний для відкату змін, але сам по собі не є повноцінною резервною копією: він залежить від базового диска та файлів VM.

## 4. Мережеві режими VirtualBox

| Режим | Призначення | Типова поведінка |
|---|---|---|
| NAT | Простий вихід VM в інтернет | VM може ініціювати зовнішні з'єднання; вхідні з'єднання з LAN за замовчуванням не налаштовані |
| Bridged | Підключення VM до фізичної локальної мережі | VM виглядає як окремий пристрій LAN та може отримати адресу від роутера |
| Host-only | Приватна мережа між хостом і VM | Зв'язок через окрему віртуальну мережу; сам по собі доступу до інтернету не дає |
| Internal Network | Ізольована мережа між VM | VM у цій мережі можуть обмінюватися даними; хост не є її учасником |

Для лабораторної роботи практично перевірялися NAT, Bridged та Host-only. Фактичні результати й напрямки успішного/неуспішного ping наведені у `02-lab-report.md`.

### IP-адреса та Gateway

IP-адреса ідентифікує мережевий інтерфейс та використовується для доставки пакетів. Gateway (шлюз) — пристрій, через який комп'ютер відправляє пакети до інших мереж, коли адресат не знаходиться в локальній підмережі. У домашній мережі шлюзом зазвичай є роутер.

Приклад із Bridged-підключення лабораторної VM:

- адреса Ubuntu: `192.168.0.137`;
- gateway: `192.168.0.1`;
- зовнішня адреса для перевірки: `1.1.1.1`.

### Корисні команди для перевірки мережі

```bash
ip a
ip -4 -br addr
ip route
ping -c 2 1.1.1.1
ping -c 2 ubuntu.com
```

- `ip a` показує мережеві інтерфейси й адреси.
- `ip route` показує таблицю маршрутів, зокрема маршрут за замовчуванням.
- `ping` перевіряє доступність адреси; ping за доменом також перевіряє DNS-розв'язання.

## 5. DNS

DNS перетворює доменні імена (наприклад, `ubuntu.com`) на IP-адреси. У лабораторній роботі навмисно видаляли `/etc/resolv.conf`, після чого запит за доменом завершувався помилкою `Temporary failure in name resolution`. Після відновлення snapshot `clean` DNS-запит знову працював.

## 6. Диски та файлові системи

Важливо відрізняти:

- **віртуальну місткість диска** — максимальний обсяг, який гостьова ОС бачить як диск;
- **фактичний розмір файлу диска на хості** — скільки місця цей файл зараз займає на фізичному накопичувачі;
- **розділи, LVM і файлову систему** — структуру всередині диска, де розміщуються дані.

У цій VM диск VDI мав віртуальну місткість 30 GB та динамічне виділення простору. В Ubuntu використовувалася схема з розділом `/boot` і LVM для кореневої файлової системи `/`.

Корисні команди:

```bash
lsblk
df -h
free -h
nproc
```

- `lsblk` показує диски, розділи та логічні томи.
- `df -h` показує використання змонтованих файлових систем.
- `free -h` показує використання пам'яті всередині гостьової ОС.
- `nproc` показує кількість процесорів, доступних поточному процесу/гостьовій ОС.

Гіпервізор не може безпечно просто відрізати кінець віртуального диска: вільний сумарний обсяг не гарантує, що дані розташовані лише на початку. Для реального зменшення віртуальної місткості треба спершу підготувати файлову систему, LVM і розділи та перенести дані на менший диск. Інший сценарій — очистити вільні блоки нулями та виконати Compact для динамічного диска: це може зменшити файл на хості, але не змінює віртуальну місткість.

## 7. Експорт та міграція VM

**OVA** — переносимий архів Virtual Appliance, який містить опис VM та образ її диска. Після перенесення OVA на інший комп'ютер його можна імпортувати через VirtualBox → File → Import Appliance.

Для одночасної роботи оригіналу та копії потрібно уникати дублювання MAC-адрес. Після імпорту варто переконатися, що призначено нові MAC-адреси, а hostname копії відрізняється від оригіналу. Для зв'язку VM з іншими пристроями тієї самої фізичної LAN зазвичай обирають Bridged; сама нова MAC-адреса не перемикає VM у цей режим.

## 8. Ресурси хоста та гостьової системи

Показники `nproc` і `free -h`, виконані всередині Ubuntu, описують ресурси, які бачить гостьова ОС, а не весь фізичний комп'ютер.

Водночас у Windows Task Manager можна перевіряти загальне навантаження хоста: RAM, CPU, доступну пам'ять та кількість логічних процесорів. Виділена VM пам'ять не дорівнює гарантовано постійному фактичному споживанню RAM хоста.
